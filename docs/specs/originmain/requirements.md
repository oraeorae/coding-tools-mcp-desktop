# 需求文档：origin/main 上游集成

## 功能概述

把 `origin/main` 截至 `e3ba1818b8ad5dca61e268762ac6383521619b4c` 的 21 个提交合并到当前 `codex/desktop-reliability-0.3.0` 分支，在引入上游审计、工作区上游 MCP、FRP TLS、受限扫描、跨平台执行和 macOS TCC 修复的同时，保留本地 0.3.7 已实现能力与所有未提交工作。

## 历史经验与坑

- **可复用经验**：先固定上游 SHA、保存工作树恢复点，再用三方合并处理真实冲突；完成后必须跑后端、前端与安装相关回归。
- **必须规避的坑**：不能用 `reset --hard`、整文件接受一侧或直接覆盖的方式处理冲突；不能降低 0.3.7 版本；不能删除浏览器桥、Actions PDF、本地升级、请求日志、退出清理、量化 allowed roots 或研究看板。

## 术语定义

- **上游**：`origin/main`，本次固定在 `e3ba1818b8ad5dca61e268762ac6383521619b4c`。
- **本地能力**：当前分支独有的 12 个提交和合并前工作树中的已跟踪、未跟踪变更。
- **语义合并**：按两侧意图组合实现，而不是机械选择 ours 或 theirs。

## 范围边界

**In Scope**

- 建立可恢复的分支、stash 和状态清单。
- 合并固定上游 SHA，并语义解决冲突。
- 保留本地 0.3.7 功能与量化路径安全边界。
- 集成上游六组能力并完成测试、审查和生产构建。

**Out of Scope**

- 重写已有产品架构或重新设计上游功能。
- 推送远程、发布 GitHub Release 或删除用户数据。
- 在验证前替换正在运行的应用。

## 需求列表

### FR-1：可恢复地合并上游历史

**优先级：Must**

作为维护者，我想要固定上游版本并保留完整恢复点，以便任何冲突处理都能撤销。

#### 验收标准

1. WHEN 开始合并 THEN 系统 SHALL 记录本地 HEAD、上游 SHA、工作树状态并创建恢复分支与 stash。
2. IF 合并或恢复工作树失败 THEN 系统 SHALL 保留可检查的冲突状态和恢复引用，不得破坏原始改动。

### FR-2：同时保留本地与上游能力

**优先级：Must**

作为应用用户，我想要获得上游更新且不丢失本地增强，以便现有连接器、量化路径和桌面工作流继续可用。

#### 验收标准

1. WHEN 合并完成 THEN 系统 SHALL 包含上游审计、上游 MCP、FRP TLS、扫描加固、跨平台执行和 macOS TCC 修复。
2. WHILE 解决冲突 THE 系统 SHALL 保留浏览器桥、Actions PDF、本地升级、请求日志、退出清理、allowed roots 和研究看板。
3. IF 上游版本低于本地版本 THEN 系统 SHALL 保持本地 0.3.7 版本和兼容数据模型。

### FR-3：通过完整回归验证

**优先级：Must**

作为维护者，我想要对合并结果做完整验证，以便发现跨模块回归。

#### 验收标准

1. WHEN 冲突全部解决 THEN 系统 SHALL 通过 Rust 测试、Svelte 检查和生产构建。
2. IF 测试暴露契约冲突 THEN 系统 SHALL 修正原因层并补充或调整回归测试。
3. WHEN 代码审查完成 THEN 系统 SHALL 不存在未解释的高优先级问题或未解决冲突标记。

## 非功能需求

- **NFR-1（性能）**：文件读取和目录扫描继续保持有界，不恢复无界内存或全盘扫描。
- **NFR-2（安全）**：写入边界、量化 allowlist、OAuth/Actions 认证和 macOS 权限声明不得弱化。
- **NFR-3（兼容性）**：保留现有 profiles 数据兼容、30 个连接器工具和 macOS Apple Silicon 构建。

## 依赖关系

- Git 三方合并与 stash 恢复。
- Rust/Tauri、SvelteKit、Node.js 测试和构建工具链。
- 当前本地配置和已安装应用仅用于最终运行验证，不参与源代码冲突选择。
