# 需求文档：启动时恢复上次运行的服务

## 功能概述

为 Coding Tools MCP 桌面应用增加一个可配置的启动恢复能力。用户在“设置 → 通用”开启后，应用正常退出时记录各工作区仍在运行的 MCP 与 Actions 服务；下次打开应用时，仅恢复这些服务，避免每次手工逐个启动。

## 历史经验与坑

- **可复用经验**: 复用 `local_update.rs` 已验证的异步服务恢复入口和延迟启动模式。
- **必须规避的坑**: 不修改高影响面的 `AppSettings::from_data/apply_to` 链；不让普通启动恢复与升级接力重复启动同一端口；单个服务失败不能阻断其他服务。

## 术语定义

- **启动恢复**: 应用启动后，按上次正常退出时的运行快照重新启动 MCP 或 Actions。
- **运行快照**: 工作区 ID 及其 MCP、Actions 是否处于 Running 或 Starting 状态的持久化记录。

## 范围边界

**In Scope（本次要做）**

- 通用设置页提供“打开应用时自动恢复上次运行的服务”开关。
- 独立持久化开关和运行快照，不改变现有代理、密钥、工作区数据结构。
- 正常退出时原子写入快照；启动时按快照恢复。
- 与本地升级接力并存，已运行服务跳过，失败按服务隔离。
- 单元测试、前端静态检查、Rust 回归及本机安装验证。

**Out of Scope（本次不做）**

- macOS 登录时自动启动应用。
- 崩溃或强制杀进程瞬间的运行状态捕获。
- 自动恢复浏览器桥接状态。

## 需求列表

### FR-1: 配置启动恢复开关

**优先级:** Must
**用户故事:** 作为桌面应用用户，我想在通用设置中控制启动恢复，以便决定应用打开后是否自动启动服务。

#### 验收标准（EARS）

1. WHEN 用户打开通用设置 THEN 系统 SHALL 显示当前启动恢复开关状态。
2. WHEN 用户切换开关 THEN 系统 SHALL 立即持久化新状态并反馈成功或失败。
3. IF 配置文件不存在 THEN 系统 SHALL 以关闭状态安全启动。

### FR-2: 记录退出前的运行快照

**优先级:** Must
**用户故事:** 作为已开启恢复的用户，我想保留退出前仍在运行的服务集合，以便下次只恢复这些服务。

#### 验收标准（EARS）

1. WHEN 应用收到真实退出事件 AND 开关已开启 THEN 系统 SHALL 原子写入 Running 或 Starting 的 MCP/Actions 快照。
2. WHILE 界面仅被重建且应用未退出 THE 系统 SHALL 不覆盖运行快照。
3. IF 没有运行服务 THEN 系统 SHALL 保存空快照。

### FR-3: 启动时隔离恢复服务

**优先级:** Must
**用户故事:** 作为已开启恢复的用户，我想在打开应用后自动恢复服务，以便连接器尽快可用。

#### 验收标准（EARS）

1. WHEN 应用启动 AND 开关已开启 THEN 系统 SHALL 按快照恢复 MCP 与 Actions。
2. IF 目标服务已由升级接力启动 THEN 系统 SHALL 跳过重复启动。
3. IF 任一工作区或服务恢复失败 THEN 系统 SHALL 记录错误并继续恢复其余服务。
4. IF 开关关闭或快照为空 THEN 系统 SHALL 不启动任何服务。

## 非功能需求

- **NFR-1（性能）**: 启动恢复调度不得阻塞主窗口展示，文件读写应在毫秒级完成。
- **NFR-2（安全）**: 状态文件不含密钥，Unix 权限为 `0600`，写入采用临时文件后原子替换。
- **NFR-3（兼容性）**: 不修改 `profiles.json` 模型；旧版本配置和现有升级恢复文件保持可用。

## 依赖关系

- 依赖 `RuntimeSupervisor::active_tunnel_service_keys` 获取当前运行集合。
- 依赖现有 `start_mcp_service`、`start_actions_service` 恢复服务。
- 启动顺序位于 `local_update::schedule_restore` 之后。
