# 需求文档：统一请求错误日志

## 功能概述

为 Coding Tools MCP 桌面应用增加统一的请求错误日志。用户在工作区的 MCP 或 Actions 日志页可以看到进入本地服务的失败请求，以及应用主动健康检查发现的公网或本地请求失败，从而直接判断错误发生时间、服务、请求路径、状态码和原因。

## 历史经验与坑

- **可复用经验**: 现有日志按工作区保存，并通过 Tauri command 读取；新模块继续使用该边界。
- **必须规避的坑**: Cloudflare 403 可能发生在请求抵达本机以前，本机服务无法被动记录这类边缘拦截；应用主动健康检查的失败结果必须写入日志。日志不得保存鉴权头、密钥、请求正文或文件内容。

## 术语定义

- **请求错误**: HTTP 状态码大于等于 400、JSON-RPC error、工具结果 `isError=true`，或健康检查请求失败。
- **结构化日志**: 每条记录包含固定字段并以 JSON Lines 持久化的错误记录。

## 范围边界

**In Scope**

- MCP 与 Actions HTTP 请求的 4xx/5xx 结果。
- MCP HTTP 200 响应中的 JSON-RPC 错误和工具错误。
- 健康检查发现的本地、公网、OAuth 元数据请求错误。
- 工作区日志页中的错误列表、刷新、复制和清空。
- 日志脱敏、长度限制、容量轮转和解析容错。

**Out of Scope**

- Cloudflare 控制台中的完整边缘请求日志拉取。
- 成功请求审计、请求正文、响应正文和用户文件内容归档。
- 前端非请求类交互错误和操作系统崩溃日志。

## 需求列表

### FR-1: 捕获服务请求错误

**优先级:** Must
**用户故事:** 作为应用用户，我想看到 MCP 和 Actions 的失败请求，以便定位连接、鉴权和工具执行问题。

#### 验收标准（EARS）

1. WHEN MCP 或 Actions 返回 4xx/5xx THEN 系统 SHALL 写入一条包含时间、服务、方法、路径和状态码的错误记录。
2. WHEN MCP 返回 JSON-RPC error 或 `isError=true` THEN 系统 SHALL 在 HTTP 状态为 200 时仍记录该错误。
3. IF 日志写入失败 THEN 系统 SHALL 保持请求处理可用且不得令请求崩溃。

### FR-2: 记录主动健康检查失败

**优先级:** Must
**用户故事:** 作为应用用户，我想看到公网和本地健康检查错误，以便发现 Cloudflare、隧道或源站异常。

#### 验收标准（EARS）

1. WHEN 健康检查项目失败 THEN 系统 SHALL 按 MCP 或 Actions 服务写入错误记录。
2. IF 失败详情包含 HTTP 状态码 THEN 系统 SHALL 将状态码保存为结构化字段。

### FR-3: 在应用中查看和管理错误

**优先级:** Must
**用户故事:** 作为应用用户，我想在现有日志页查看、复制和清空请求错误，以便排查并整理问题。

#### 验收标准（EARS）

1. WHEN 用户打开 MCP 或 Actions 日志页 THEN 系统 SHALL 显示该工作区和服务最近的请求错误，并每 3 秒自动刷新。
2. WHEN 用户点击复制 THEN 系统 SHALL 将当前错误记录复制到剪贴板。
3. WHEN 用户确认清空 THEN 系统 SHALL 仅删除当前工作区和当前服务的请求错误。

### FR-4: 控制日志安全与体积

**优先级:** Must
**用户故事:** 作为应用用户，我想让错误日志可长期开启，同时不泄露凭据或无限占用磁盘。

#### 验收标准（EARS）

1. WHILE 写入错误记录 THE 系统 SHALL 不读取或保存 Authorization、token、secret、请求正文和响应正文。
2. WHEN 单个服务错误日志达到 1 MiB THEN 系统 SHALL 轮转为一个历史文件，并只保留当前文件和一个历史文件。
3. IF 错误消息超过 500 个字符或包含换行 THEN 系统 SHALL 截断并压缩成单行。

## 非功能需求

- **NFR-1（性能）**: 单次请求最多追加一条通用 HTTP 错误；日志锁只覆盖文件轮转与追加。
- **NFR-2（安全）**: 日志采集器不接收请求头、请求正文或响应正文。
- **NFR-3（兼容性）**: 沿用现有 Tauri 2、Axum 0.8 和 Svelte 5，不引入新的运行时依赖。

## 依赖关系

- 依赖现有工作区日志目录 `log_dir_for_profile`。
- 依赖现有 MCP、Actions listener 和健康检查 command。
